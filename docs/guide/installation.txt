Installation
============

Requirements
------------

Python 3.10 to 3.13 supported.

Django 4.2 to 5.2 supported.

Installation
------------

1. Install with **pip**:

   .. code-block:: sh

       python -m pip install django-resume

2. Add django-resume to your ``INSTALLED_APPS``:

   .. code-block:: python

       INSTALLED_APPS = [
           ...,
           "django_resume",
           ...,
       ]

django-resume's editable templates load HTMX where needed. You do not need to
install or configure django-htmx to use the built-in editing views.


Uploaded images and media
-------------------------

Avatar and signature images are stored with Django's default storage under
``uploads/``. django-resume only accepts JPEG, PNG, GIF and WebP files, detects
the format from the file content rather than the client's filename or content
type, and stores each upload under a random name with the extension of the
detected format (for example ``uploads/3f2a…c9.png``). SVG, HTML and other
files are rejected, and uploads are limited to 2 MB. Lossless WebP (VP8L)
dimensions are read from its packed header, including asymmetric images;
truncated headers and invalid VP8L signatures are rejected. Both declared and
actual upload sizes are checked: copying retains at most 2 MiB plus one byte
and stops consuming chunks immediately when the limit is exceeded.

If an upload or the plugin database mutation fails, the editing views delete
only uploads newly created by that operation. Existing images and plugin data
are preserved. Storage must support deletion for compensation to succeed;
a backend deletion failure is reported rather than silently ignored. Custom
views using ``ImageFormMixin`` must call ``cleanup_new_image_uploads()`` if
persistence fails after successful validation.

Serve ``MEDIA_URL`` so that the content type follows the stored file extension,
and keep ``X-Content-Type-Options: nosniff`` enabled (Django's
``SecurityMiddleware`` sends it by default for responses it handles; configure
your web server to send it for media files). Serving media from a separate
domain is a further defense in depth.

The editing views require ``POST`` for saves and ``DELETE`` or ``POST`` for
item deletes, so Django's CSRF protection applies to every change. If you
override the editable templates, keep the ``X-CSRFToken`` header that the
bundled pages set for htmx requests.

Admin JavaScript
----------------

The plugin admin editor loads HTMX 2.0.3 from unpkg with subresource integrity
and ``crossorigin="anonymous"``, matching the bundled page templates. The
browser must be able to reach this CDN for admin plugin forms (save, add item,
and delete item) to work; a script
whose bytes do not match the pinned hash is rejected by the browser.

Education data migrations
-------------------------

Migration 0003 reads and writes only the database alias selected by ``migrate
--database``. Before migrating backwards, it checks every resume before changing
any row. Legacy education can represent at most one item and only ``school_name``,
``school_url``, ``start`` and ``end``. Nonempty degrees, extension fields and
custom flat metadata refuse rollback with ``IrreversibleError``. Generated item
IDs, positions and the default "Education" title are structural metadata.

Before rollback, take a database-native backup of the selected database and
export each resume's complete ``plugin_data`` (for example with Django
``dumpdata django_resume.Resume --database ALIAS --output resumes.json``).
Keep both files outside public media. To proceed, explicitly curate education to
one legacy-compatible item, retaining the export for recovery, then retry.
Restore the database backup to recover all original values if needed.

Forward migration also preflights all legacy education mappings. Unknown fields
whose values are neither null nor an empty string refuse the upgrade before any
write, including extension-only mappings. Back up and export as above, then
explicitly curate those values into the supported fields or retain them in the
backup before retrying. Already-list-shaped data is unchanged.
